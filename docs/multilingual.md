# Ручные переводы RU / BE / EN

Содержимое WordPress и PHP-шаблоны работают вместе: запись хранит текст и язык, а PHP задаёт внешний вид. Для каждой языковой версии нужна отдельная запись. Бесплатный Polylang связывает их между собой. Машинный перевод не используется.

## Как запустить

1. Установите бесплатный Polylang в WordPress и добавьте языки: русский (`ru`, основной), белорусский (`be`) и английский (`en`). При настройке назначьте существующим русскоязычным записям русский язык. Сохраните постоянные ссылки в **Настройки → Постоянные ссылки**.
2. Для новой обычной страницы создайте русскую запись, выберите шаблон **«Редактируемая страница (RU/BE/EN)»** и заполните заголовок, текст и, при необходимости, изображение. Создайте белорусскую и английскую версии через значки `+` Polylang, задайте им тот же шаблон и внесите переводы в редакторе WordPress. Polylang сохранит связь между записями и адреса страниц.
3. Переведите подписи шапки и подвала в **Языки → Переводы строк**, группа **«Тема сайта»**. Здесь можно затем исправлять формулировки без правки кода.
4. Для существующих страниц с собственным PHP-шаблоном оставьте один шаблон оформления для всех языков. Перенесите редактируемые абзацы из PHP в содержимое страницы или в поля WordPress; в шаблоне выводите их через `the_content()` или поля текущей записи. Создайте и свяжите переводы этих записей в Polylang. Сложные страницы, например раздел Зинченко, переносите по одной: там текст и структура страницы тесно связаны.
5. Для записей, категорий и данных в дополнительных полях создавайте переводы отдельно. Ссылки на страницы по числовым ID в общей шапке и подвале уже проходят через `mbio_page_link()` и переходят на связанную версию, если она есть. Для новых запросов записей указывайте текущий язык и при необходимости переводите ID категории через `pll_get_term()`.

Пример для шаблона:

```php
<?php the_content(); // Текст записи на текущем языке. ?>
<a href="<?php echo esc_url( mbio_page_link( 281 ) ); ?>">
    <?php echo esc_html( mbio_t( 'Структура института' ) ); ?>
</a>
```

Если PHP-шаблон выводит список записей WordPress, берите записи текущего языка:

```php
$items = get_posts( array(
    'post_type' => 'post',
    'numberposts' => 10,
    'lang' => mbio_current_language(),
    'suppress_filters' => false,
) );
```

Для категорий, указанных в старом коде числовыми ID, также создайте переводы категорий и получайте их ID через `pll_get_term( $russian_category_id )`.

Поле ACF, привязанное к фиксированной странице, можно читать по `mbio_translated_post_id( $page_id )`. В бесплатном Polylang значения пользовательских полей не становятся переводами сами по себе: их нужно заполнить в каждой языковой записи. Если связанной страницы ещё нет, `mbio_page_link()` временно ведёт на исходную русскую страницу; языковая кнопка на текущей странице появляется только при наличии связанного перевода. После создания пары/тройки страниц проверьте соответствие ссылок и наполните все общие строки до публикации языковых версий.

Код темы сам по себе не создаёт переводы в рабочей базе WordPress. Сначала установите и настройте Polylang на рабочем сайте, затем переносите содержимое и связывайте записи. PDF и другие документы можно прикреплять как файлы; переводить их содержимое для работы переключателя не требуется.
